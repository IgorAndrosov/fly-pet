# fly-pet

Питомец-муха на рабочем столе: живёт в прозрачном окне, периодически «думает» через LLM и может
убирать файлы с рабочего стола (только перенос в корзину проекта).

## Текущее состояние

Готово: скелет пакета, конфиг и состояние, логирование, прозрачное окно со спрайтами, анимации,
перетаскивание, облачко реплик, потребности, локомоция (два режима: рабочий стол и чужие окна),
перелёты стол↔окно, отпугивание курсором, потирание лапок, иконка в трее, сборка в exe.

Окружение — проектная venv `.venv` (глобально ничего не ставить): PyQt6, Pillow, PyYAML, httpx, pytest.
Для сборки exe владелец ставит PyInstaller в ту же venv.

## Планы

- **Безопасные действия** — уборка рабочего стола с переносом файлов в корзину проекта (не удаление),
  отчёт о работе, сон при простое. Всё под белым списком, по умолчанию в режиме «только докладывать».
- **«Верхний мозг» на DeepSeek** — выбирает, чем заняться, и комментирует происходящее.
- **Мозг дрозофилы.** Планируется подключить настоящую модель мозга плодовой мухи: спайковую
  connectome-модель с реальными весами FlyWire и LIF-нейронами, у которой на выходе «скорость ходьбы +
  смещение поворота». Тогда походка перестанет быть скриптовой — ею будет управлять модель, а спрайт
  станет исполнителем её выходов. Если модель не заведётся на текущем железе, останутся скриптовые
  анимации, и мы скажем об этом прямо.

## Как запустить питомца

Из `cmd` или PowerShell:

```bat
cd D:\Projects\fly-pet
.venv\Scripts\python.exe -m fly_pet --gui
```

Из git-bash:

```bash
cd /d/Projects/fly-pet && .venv/Scripts/python.exe -m fly_pet --gui
```

Открывается окно консоли (это «пульт» питомца — оставить открытым), и на рабочем столе появляется
муха. По умолчанию она садится в правый нижний угол; её можно перетаскивать левой кнопкой мыши —
новая позиция запоминается в `_data/state.json`.

**Управление — через иконку в трее** («Муха-питомец»): спрятать/показать, стоять на месте, сон,
не бояться курсора, отчёт (заглушка), о программе, выход. Контекстного меню на самой мухе нет,
`Esc` не используется. Курсор отпугивает муху (рывок / паника); отключается галочкой
«Не бояться курсора» в трее.

## Поведение на рабочем столе

Муха не сворачивается вместе со всеми окнами (`Win+D` / «Свернуть все»), не отображается в панели
задач и Alt+Tab, и не является «поверх всех окон». Обычные окна и уведомления могут её перекрыть —
это осознанно. После «свернуть все окна» / `Win+D` сторож возвращает муху на рабочий стол
(срабатывает только когда поверх неё лежит именно рабочий стол; обычные окна её по-прежнему
перекрывают).

## Сборка в exe

PyInstaller ставит владелец. Затем:

```bash
.venv/Scripts/python.exe tools/build_exe.py
```

`--dry-run` печатает команды без сборки.

Готовые сборки:

| Путь | Что это |
|------|---------|
| `dist/fly-pet/` | Вариант «папка» (`--onedir`): быстрее стартует, рядом лежат DLL и ресурсы |
| `dist/fly-pet-onefile.exe` | Вариант «один файл» (`--onefile`): удобно носить, дольше распаковка при старте |

При запуске exe данные пишутся в `_data` **рядом с exe** (переносимая сборка). Ресурсы
(спрайты, `config/default.yaml`) берутся изнутри сборки.

## Как выключить питомца

1. Пункт «Выход» в меню трея (сохраняет состояние и останавливает таймеры).
2. В окне консоли, из которого он запущен — `Ctrl+C` (или закрыть это окно).
3. Если окно консоли потерялось — выключить по имени процесса:

```powershell
Stop-Process -Id (Get-CimInstance Win32_Process -Filter "name like '%python%'" |
  Where-Object { $_.CommandLine -like '*fly_pet*' }).ProcessId -Force
```

Для сборок в exe имена процессов другие, и у варианта «один файл» exe запускает **дочерний** процесс
с тем же именем — при ручном снятии надо убить оба:

```powershell
Stop-Process -Name fly-pet,fly-pet-onefile -Force -ErrorAction SilentlyContinue
```

Пункт «Выход» в трее делает это сам и сохраняет состояние — это правильный способ выключения.

## Данные

Состояние, логи, корзина и локальные настройки — в `_data/` (в git не попадает, из Syncthing исключён
строкой `fly-pet/_data` в `D:\Projects\.stignore`). При запуске из репозитория — `_data` в корне
проекта; при запуске exe — `_data` рядом с ним.

## Безопасность (заложено)

- Уборка = только перенос в `_data/trash`, никакого удаления файлов.
- `dry_run` по умолчанию: реальные действия — только после явного разрешения.
- Без автозапуска и без глобальных установок.
