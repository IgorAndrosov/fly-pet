# Задача 14: муха всё ещё остаётся под рабочим столом (жест — «свернуть все окна» уголком панели задач)

## Что происходит у владельца (воспроизведено, сборка 01:08, `dist/fly-pet-onefile.exe`)

Владелец сворачивает все окна **кликом по уголку панели задач** (в Win11 это XAML-механизм, не
`ToggleDesktop`). Муха исчезает и не возвращается, пока не развернуть окно.

Живая запись (0,25 с, `fly_live_monitor.py`, файл `...\hermes\cache\scratch\fly_trace.txt`), 40+ секунд
подряд:

```
НЕВИДИМА родитель=#32769  в_точке=SysListView32  над_ней=Progman  индекс_мухи=27 Progman=26
```

То есть: рабочий стол реально лежит над мухой, **родитель окна так и остался обычным** — усыновление
(`SetParent(Progman)`) не удержалось.

## Причина (найдена в коде, подтверждена её же логом)

`fly_pet/window.py`, `_is_show_desktop_active()` идёт по z-порядку **с самого верха** и выходит
`False` на первом же видимом, не `cloaked` и не попавшем в `_ZORDER_SKIP_CLASSES` окне. На Win11 26200
верх z-порядка занят оболочкой и XAML-слоем: замеренный список (мой `probe_zorder2.py`) —
`XamlExplorerHostIslandWindow`, `Microsoft.UI.Content.DesktopChildSiteBridge`, `DirectUIHWND`,
`ShellHandwritingCanvas`, `ThumbnailDeviceHelperWnd`, `ForegroundStaging`, `GDI+ Hook Window Class`,
`tooltips_class32`, `IME`, `MSCTFIME UI`, `_q_titlebar`. Поэтому:

1. `_on_desktop_reassert` → `_is_desktop_on_top()` → True → `_adopt_desktop_parent()` → `SetParent(Progman)`.
2. Следующий тик: `_desktop_adopted` = True → `if not self._is_show_desktop_active(): _release_desktop_parent()`.
   `_is_show_desktop_active()` спотыкается на XAML-окне сверху → False → **немедленно отпускает** окно.
3. Дальше цикл «усыновил → отпустил» повторяется; в логе владельца это видно как **две** записи
   `SetWindowBand(ZBID_DESKTOP) отказ … — выбран SetParent(Progman)` (01:14:04 и 01:18:41), а муха
   всё время висит под столом.

## Что сделать

Заменить «обход верха z-порядка» на прямой ответ на вопрос «рабочий стол сейчас **над мухой**?»:

1. `at = WindowFromPoint(центр окна мухи)`; если класс `at` ∈ `{SysListView32, SHELLDLL_DefView, Progman,
   WorkerW}` **или** `GetAncestor(at, GA_ROOT)` ∈ `{Progman, WorkerW}` → рабочий стол над мухой.
2. Иначе: `above = GetWindow(hwnd_мухи, GW_HWNDPREV)` — если класс `above` ∈ того же набора → тоже над мухой.
3. Верх z-порядка не обходить вообще (там живёт XAML-оболочка). Из прежнего детектора оставить только
   признак `_is_our_hwnd(at)` (наш собственный XAML-«переход» сверху не должен путать).
4. Стабильность: усыновлять после **2 подряд** подтверждений (тик ≈ `desktop_reassert_ms`), отпускать —
   только после **3 подряд** отрицаний, чтобы не было дребезга «усыновил/отпустил».
5. Логировать **на уровне INFO** каждое усыновление и отпускание с причиной и наблюдаемым классом
   (например: `усыновил: стол над мухой (в_точке=SysListView32)` / `отпустил: стол больше не над мухой
   (в_точке=Chrome_WidgetWin_1, над_ней=Hermes)`) — чтобы следующий отчёт владельца читался из лога.
6. Проверить, не пересоздаёт ли Qt нативное окно при `SetParent`: в живой записи окно мухи несколько раз
   «исчезало» из перечисления верхнеуровневых окон, а её hwnd при этом менялся — если окно пересоздаётся,
   усыновление надо переприменять (и это должно попадать в INFO-лог).

```bash
# 1) свернуть все окна кликом по уголку панели задач (это жест владельца), 12 с ожидания
.venv/Scripts/python.exe "C:/Users/igora/AppData/Local/hermes/cache/scratch/taskbar_showdesktop.py" 12 2
# 2) живая запись состояния (класс точки, родитель, индексы) — 25 с
.venv/Scripts/python.exe "C:/Users/igora/AppData/Local/hermes/cache/scratch/fly_live_monitor.py" 25
# 3) заодно ногий ToggleDesktop не должен сломаться
.venv/Scripts/python.exe "C:/Users/igora/AppData/Local/hermes/cache/scratch/verify_desktop_fix.py"
```
Скрипты находят окно по заголовку `fly-pet`; питомца перед проверкой запускать так, чтобы он был один
(`.venv/Scripts/python.exe -m fly_pet --gui`).

Критерий приёмки:
- При показанном рабочем столе состояние `НЕВИДИМА` не длится дольше ~1,5 с, затем окно усыновлено
  (`родитель=Progman`) и муха видна.
- После возврата окон родитель снова обычный, обычное окно её перекрывает, `topmost=False`.
- В логе нет дребезга: одна запись «усыновил» и одна «отпустил» на один цикл сворачивания/разворота.

## Чего нельзя
- Делать окно `topmost` (`always_on_top`, постоянный `WS_EX_TOPMOST`) — запрещено владельцем.
- Менять спрайты, потребности, облачко, LLM, локомоцию (кроме выпуска родителя перед посадкой),
  `tools/build_exe.py`, `_debug_run.py`.
- Коммитить, ставить пакеты, собирать exe (пересоберёт владелец).
