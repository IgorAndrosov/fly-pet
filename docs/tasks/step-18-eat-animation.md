# Задача 18: настоящая анимация поедания иконки — укусы полукругами по всей иконке

## Что не так сейчас
Владелец: «муха подходит к файлу и через пару секунд он пропадает. Анимации поедания нет.» Нужно:
муха подходит к **фактическому краю иконки**, откусывает **по чуть-чуть**, проходит так **по всей иконке**,
и изображение исчезает постепенно — кусками-полукругами.

## Как это сделать (проверенный подход, иконку explorer перерисовать нельзя)
Иконку на рабочем столе рисует explorer, поэтому «съедаем» её **своим оверлеем**:

1. **До создания файла** снять экран (`QScreen.grabWindow(0)`) — это фон рабочего стола «как будто иконки
   нет». Из него берётся вырезка клетки иконки.
2. Создать тестовый файл, дождаться иконки (как сейчас), получить её прямоугольник в экранных координатах.
   Снять экран ещё раз — из разницы с (1) получить **картинку иконки** (само изображение + подпись в клетке).
3. Показать **оверлей**: прозрачное для мыши окно (`WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW`,
   без активации), ровно по прямоугольнику иконки, в котором нарисовано: фон из (1) + иконка из (2),
   **маскированная укусами**. Пока укусов нет — картинка неотличима от настоящей иконки.
4. **Укусы**: каждый укус — полукруг (полдиска) радиусом `8…14 px` с центром на пути мухи; в маске он
   «вырезает» часть иконки, и там виден фон. Укусы накапливаются; после каждого — кадр анимации `chew`
   и облачко с короткой репликой на первый/последний укус (например «Хрум!», «Всё, доела»).
5. **Маршрут**: муха идёт **по фактическому краю изображения** (bbox непрозрачных пикселей иконки, не всей
   клетки), а не по её центру: обход периметра по часовой, затем зигзаг внутрь, пока не съедено всё.
   Шаг между укусами — примерно радиус укуса, чтобы не оставалось целых кусков. Она должна **реально
   перемещаться** (её окно следует за точками укусов), а не стоять на месте.
6. **Порядок финала важен:** сначала перенести файл в карантин (иконка исчезает на самом деле), затем
   снять оверлей — иначе после снятия оверлея иконка «вернётся». Файл по-прежнему **только переносится**
   в `_data/trash/`, ничего не удаляется.
7. Оверлей **обязательно снимать при любом выходе** (успех, исключение, остановка демо): один оверлей на
   демо, никаких «залипших» прозрачных окон на рабочем столе.
8. Зи-порядок: оверлей — над иконками рабочего стола, **муха — над оверлеем** (иначе её закроет).
   Если рабочий стол показан (режим topmost из задачи 15) — оверлей тоже должен быть виден.
9. Логи INFO: `укус 3/24: центр=(x,y) r=11, осталось 71%` (для отладки), `съедено 100%`, `оверлей снят`.
   Всего укусов — 15–30 в зависимости от размера иконки.

## Тайминг
Весь обход — 6–10 секунд: укус примерно каждые 0.25–0.4 с, между укусами муха переходит к следующей точке
(короткие шаги/подскоки, без длинных полётов). Не растягивать на полминуты и не «схлопывать» в 2 секунды.

## Как проверять (мои обязательные замеры)
```bash
cd D:/Projects/fly-pet
FLY_PET_DATA_DIR=D:/Projects/fly-pet/_data_check .venv/Scripts/python.exe -m fly_pet --demo-eat --gui
```
1. **Прогресс укусов виден на экране**: снимок клетки иконки каждые ~0.7 с — доля пикселей, совпадающих
   с исходной иконкой, должна **монотонно убывать** до ~0 (я проверю по снимкам).
2. **Муха ходит по иконке**: её прямоугольник в течение демо должен быть в пределах клетки иконки
   (плюс-минус), а не в стороне.
3. **Оверлея не остаётся** после финала и его нет в списке окон (проверю `EnumWindows`).
4. Файл: на рабочем столе исчез, в `_data/trash/` — есть, не удалён.
5. `stats.eaten` +1; муха **рисуется** после демо; `pytest -q` зелёный.
6. Если файл по какой-то причине не найдётся на столе — демо аккуратно завершается, оверлей снят.

## Чего нельзя
- Удалять файлы, трогать чужие файлы/иконки.
- Менять спрайты, LLM, Show Desktop/topmost, сборку.
- Оставлять оверлей или его процесс при падении.
- Коммитить, ставить пакеты, собирать exe.

## Отчёт
Коротко: как устроен оверлей и маска, сколько укусов/секунд на реальной иконке (лог), чем проверял, что
осталось неуверенным (например, поведение при анимации иконок рабочего стола или смене обоев).
