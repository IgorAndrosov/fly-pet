# Задача 20: монитор по номеру — через Win32, а не по имени Qt

## Что выяснилось на реальной машине (ИИшница, два монитора)
Сборка 15:32, лог:

```
WARNING [resolve] монитор \\.\DISPLAY1 не найден — беру основной C30SK PRO
INFO [build_app] мониторов: 2; экран: C30SK PRO 2560x1080 at (0,0) primary=True;
     область ходьбы: (0,0)-(2560,1032)
```

То есть `window.monitor: 1` **не нашёл** `\\.\DISPLAY1`, потому что на этой машине `QScreen.name()` равен
EDID-имени монитора (`C30SK PRO`), а не пути устройства. Сработал аварийный откат на основной экран —
повезло, что «первый» и есть основной. При `monitor: 2` она тоже ушла бы на основной.

## Что сделать

1. **DPI-awareness на старте приложения** (до создания окон): `SetProcessDpiAwarenessContext(
   DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2)` с откатом на `SetProcessDpiAwareness(2)` и старый
   `SetProcessDPIAware()`. Сейчас он включается только при чтении иконок рабочего стола.
2. **Перечисление мониторов через Win32**: `EnumDisplayMonitors` + `GetMonitorInfoW` → для каждого:
   `szDevice` (`\\.\DISPLAY1`, `\\.\DISPLAY2`, …), `rcMonitor`, `rcWork`, признак primary
   (`MONITORINFOF_PRIMARY`). Записать в лог все найденные мониторы одной строкой:
   `мониторы: \\.\DISPLAY1 2560x1080 at (0,0) work=(0,0,2560,1032) primary; \\.\DISPLAY2 1920x1080 at (2560,0) work=…`.
3. **Выбор экрана** (`fly_pet/screens.py`): порядок поиска
   a) по имени Qt (`QScreen.name()` == `\\.\DISPLAY<n>`) — как сейчас;
   b) если не нашлось — по Win32: взять прямоугольник `rcMonitor` монитора `\\.\DISPLAY<n>` и найти
      экран Qt, чей `geometry()` (с учётом `devicePixelRatio`) совпадает с ним (допуск 1–2 px; при
      несовпадении — по центру прямоугольника);
   c) если и это не удалось — WARNING и основной экран (как сейчас).
   В INFO писать, **как** нашли: `монитор 1: C30SK PRO (по Win32 \\.\DISPLAY1), область ходьбы …`.
4. **Проверка согласованности**: если `rcMonitor` и `QScreen.geometry()` расходятся больше чем на 2 px
   (разный DPI), писать WARNING с обоими прямоугольниками — это поможет диагностировать раскладки с
   масштабированием.
5. Ничего больше не менять: фильтр окон, локомоция, демо-поедание, трей, мозг, сборка — как есть.

## Тесты (обязательно)
Без GUI, на фейковых данных:
- Win32-список с `\\.\DISPLAY1/2` и Qt-список с EDID-именами — `monitor: 1` и `2` находят нужный экран
  **по прямоугольнику**, `primary` — основной, `all` — объединение;
- нет соответствия ни по имени, ни по прямоугольнику → откат на основной + `fallback=True`;
- расхождение DPI (Qt 1280x720 при Win32 2560x1440, dpr=2) → экран находится, в логе WARNING.
