# Задача 13: муха исчезает под рабочим столом после «Свернуть все окна»

## Что происходит (замерено на живом питомце, сборка `dist/fly-pet-onefile.exe`, не догадка)

Владелец: свернул все окна → муха исчезла и не вернулась; появилась только когда он развернул
одно из окон. Мои замеры:

| Замер | Результат |
|---|---|
| `Shell.Application.ToggleDesktop()` (то же, что Win+D), точка центра окна мухи | `WindowFromPoint` → `SysListView32|FolderView` — рабочий стол сверху |
| Полный верхнеуровневый z-порядок после Win+D | **`Progman` индекс 24, окно мухи индекс 27** — рабочий стол выше мухи |
| `WorkerW` (13 окон) | все НИЖЕ мухи; мешает именно `Progman` |
| Принудительный `SetWindowPos(окно_мухи, HWND_TOP, SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE)` | вернул 1, но окно встало **сразу ПОД `Progman`** (индекс 25 при 24) — обычные окна в этом состоянии выше рабочего стола не поднимаются |
| То же для чужого окна (Hermes) | так же: вернул 1, остался под `Progman` — это не особенность нашего окна, а полоса оболочки |
| `SetWindowPos(окно_мухи, HWND_TOPMOST)` | вернул 0, `GetLastError` = 1400 |
| `SetWindowPos(окно_мухи, HWND_NOTOPMOST)` / возврат окон | `Progman` уехал на индекс 375 — поэтому муха «появляется, когда развернуть окно» |

Вывод: **сторож `desktop_reassert` работает вхолостую** — он делает ровно тот `SetWindowPos(HWND_TOP)`,
которого недостаточно. Наш сторожий код (`fly_pet/window.py`, `_on_desktop_reassert` /
`_is_desktop_on_top` / `_raise_without_activate`) можно оставить как детектор, но поднимать надо другим
способом. `user32.SetWindowBand` на этой Windows (11, сборка 26200) экспортируется.

## Что нужно сделать

1. Муха после Show Desktop (`Win+D`) должна **оставаться видимой на рабочем столе**, и при этом
   **не превращаться в «поверх всех окон»**: обычное окно, развёрнутое над ней, обязано её
   перекрывать (это замороженное решение проекта).
2. Проверить и реализовать рабочий механизм — перебрать оба кандидата, оставить тот, что реально
   работает, и написать в отчёте, какой выбран и почему:
   - **полоса окна**: `SetWindowBand(hwnd, NULL, ZBID_DESKTOP)` (1) — окно попадает в ту же полосу,
     что рабочий стол, и внутри полосы обычный z-порядок позволит встать над `Progman`; при
     приземлении на чужое окно / возврате из Show Desktop — вернуть `ZBID_DEFAULT` (0) и вставлять
     окно над целевым окном, как сейчас. Если вызов не разрешён без uiAccess — зафиксировать ошибку
     в логе и назвать это в отчёте честно;
   - **усыновление рабочим столом**: `SetParent(hwnd, Progman)` (подход Rainmeter / Wallpaper
     Engine) — окно становится дочерним у рабочего стола: видно всегда, когда видно сам рабочий стол,
     и по-прежнему ПОД обычными окнами. При посадке на чужое окно — `SetParent(hwnd, NULL)` и
     вставка над целевым окном, при возврате на стол — обратно. Обязательно проверить, что Qt это
     переживает: прозрачность, отрисовка спрайта, перетаскивание мышью, попадание `WindowFromPoint`
     в окно, корректные координаты (у дочернего окна координаты становятся клиентскими —
     пересчитывать через `MapWindowPoints`/`ScreenToClient`), работа облачка реплик.
3. Триггер — существующий сторож (`desktop_reassert`, `desktop_reassert_ms`), но `_raise_without_activate`
   заменяется на выбранный механизм. Обязательно: не вызывать дорогие операции каждый тик —
   менять состояние только при переходе «рабочий стол выше мухи ⇄ обычное состояние».
4. Не сломать: посадку на чужие окна и ходьбу по полосе заголовка, перелёты стол↔окно, отпугивание
   курсором, перетаскивание, фильтр окон, `never_minimize`, `tool_window`, конфиг и тесты.
5. Добавить в `docs/decisions.md` короткий раздел с выбранным механизмом и почему (одно решение —
   один абзац).

Критерий приёмки (мой замер на собранной версии):
```
после ToggleDesktop(), в течение 1.5 с:
  WindowFromPoint(центр мухи) == окно мухи (Qt…|fly-pet)
  индекс мухи в цепочке верхнеуровневых окон < индекса Progman
после возврата окон:
  окно, поднятое над мухой, её ПЕРЕКРЫВАЕТ (муха не в полосе выше обычных окон)
  муха ходит, садится на чужие окна, пугается курсора
```
