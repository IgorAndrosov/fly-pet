# Задача 15: откатить SetParent и держать видимость через временный topmost

## Главное: механизм из задачи 13/14 негоден — он убивает отрисовку

Замерено двумя опытами (свежий экземпляр, жест владельца — клик по уголку «свернуть все окна»,
`rendering_experiment.py` и `topmost_experiment.py`; критерий — сколько пикселей меняется **внутри
прямоугольника мухи** между двумя снимками экрана за 0,5 с):

| Состояние | Родитель / topmost | Меняется пикселей | Итог |
|---|---|---|---|
| сразу после запуска | top-level | 553…1132 | **рисуется** |
| стол показан, приложение усыновило окно (`SetParent(Progman)`) | child of Progman | **0** | **НЕ рисуется** — окно есть, попадает под курсор, но на экране пусто |
| после возврата окон (родитель отпущен) | top-level | **0** | **НЕ рисуется никогда** — отрисовка уже не восстанавливается |
| стол показан, вместо перепривязки сделан `SetWindowPos(HWND_TOPMOST)` | topmost=True | 660 | **рисуется и видна** |
| окна вернулись, topmost снят | topmost=False | 1237 | рисуется, обычное окно её перекрывает |

Вывод: `SetParent` на Qt-окне ломает отрисовку безвозвратно — **отказаться от усыновления полностью**.
Вместо него — временный `topmost`, пока рабочий стол сверху.

## Что сделать

1. **Удалить** машинерию усыновления: `_adopt_desktop_parent`, `_release_desktop_parent`,
   `_set_progman_parent`, `_is_adopted_native`, `_sync_adopted_native_pos`, `_sync_bubble_desktop_parent`,
   `_set_progman_parent`-хвосты, флаг `_desktop_adopted`, а также `release_desktop_parent` в
   `locomotion.py` (перед посадкой на окно) — он больше не нужен. `SetParent` не вызывать **нигде**.
2. **Оставить** детектор «рабочий стол сверху» из задачи 14 (он работает: по замеру он верно определил
   `в_точке=SysListView32`), гистерезис (2 тика на включение, 3 на выключение) и INFO-логи.
3. Вместо усыновления в `_raise_without_activate`:
   - `SetWindowPos(hwnd, HWND_TOPMOST, 0, 0, 0, 0, SWP_NOMOVE | SWP_NOSIZE | SWP_NOACTIVATE)` — когда
     стол над мухой;
   - `HWND_NOTOPMOST` — когда стол больше не над мухой.
   **Обязательно задать прототипы ctypes** (`argtypes=[HWND, HWND, c_int, c_int, c_int, c_int, c_uint]`,
   `restype=BOOL`): без них вызов возвращает 0 и ошибку 1400 — именно на этом я спотыкался в замере.
   Передавать хэндлы как `wintypes.HWND(...)`, HWND_TOPMOST/NOTOPMOST — как `wintypes.HWND(-1/-2)`.
4. Облачко реплик — тоже временно topmost, пока стол сверху (иначе реплика окажется под столом); снимать
   вместе с мухой.
5. Логи на INFO: `применил topmost: стол над мухой (в_точке=…)` / `снял topmost: стол больше не над мухой
   (в_точке=…)`. Никаких «усыновил» — этих слов в логе быть не должно.
6. Гарантии, которые надо проверить и описать:
   - постоянного `WS_EX_TOPMOST` не остаётся: после возврата окон у окна `exstyle & 0x8 == 0`;
   - при показанном столе муха **видна** и **ходит**;
   - когда стол не показан, обычное окно её перекрывает (проверить: поднять окно над ней и убедиться,
     что при её центре теперь чужое окно, а `topmost=False`).

## Как проверять (обязательный минимум, скрипты уже готовы)

```bash
C="C:/Users/igora/AppData/Local/hermes/cache/scratch"
.venv/Scripts/python.exe "$C/rendering_experiment.py"     # запуск → уголок → возврат, с подсчётом пикселей
.venv/Scripts/python.exe "$C/topmost_experiment.py"       # контрольный опыт с topmost
```
Скрипты сами запускают питомца с заголовком `fly-pet-check` и своим каталогом данных; второй из них
выключает сторожа (`desktop_reassert: false`) — чтобы мерить именно topmost.

**Критерий приёмки (по пикселям, а не по хэндлам!):**
- после клика по уголку: `пикселей меняется: > 3` и `в_точке=МУХА` → муха реально нарисована;
- после возврата окон: тоже `> 3` (отрисовка не умерла) и `topmost=False`;
- в логе по одной строке «применил topmost» и «снял topmost» на цикл, без дребезга.

## Чего нельзя
- Возвращать `SetParent` в любом виде.
- Оставлять `WS_EX_TOPMOST` навсегда или включать `always_on_top` в конфиге.
- Трогать спрайты, потребности, облачко (кроме topmost), локомоцию, LLM, `tools/build_exe.py`.
- Коммитить, ставить пакеты, собирать exe.
