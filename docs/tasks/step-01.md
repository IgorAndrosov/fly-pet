# Задача 1: скелет пакета fly-pet

Работай только внутри `D:\Projects\fly-pet`. Ничего не устанавливай (виртуальное окружение уже создано
владельцем: `.venv`, в нём есть PyQt6, Pillow, PyYAML, httpx, pytest). Другие проекты в `D:\Projects`
и папку `D:\hermes` не трогай. Язык интерфейса, комментариев и README — русский. Файлы — UTF-8 без BOM.

Контекст проекта читай в `docs/plan-stage1.md` и `docs/decisions.md` (согласованные решения; код не
должен им противоречить).

## Что сделать в этом шаге
Только скелет запускаемого пакета. Никакого PyQt6 в этом шаге: он должен запускаться и проверяться
без графики.

1. `fly_pet/__init__.py` — докстринг пакета по-русски и `__version__ = "0.1.0"`.
   Пакет плоский, в корне репозитория (не `src/`): чтобы `python -m fly_pet` работал без установки.
2. `fly_pet/__main__.py` — точка входа:
   - `python -m fly_pet` печатает ровно одну строку вида `fly-pet ok, версия 0.1.0, Python 3.13.14`
     (интерпретатор брать из `sys.version_info`, не хардкодить);
   - `python -m fly_pet --version` печатает только номер версии;
   - `python -m fly_pet --help` показывает осмысленную русскую справку (argparse, `description` по-русски:
     питомец-муха на рабочем столе; в этом шаге реальных опций кроме `--version` нет);
   - вход в `if __name__ == "__main__": main()` и функцию `main(argv=None) -> int`.
3. `requirements.txt` — ровно эти зависимости с нижними границами версий: PyQt6, Pillow, PyYAML, httpx
   (pytest — в отдельную строку с комментарием `# для тестов`, либо в `requirements-dev.txt`, как
   посчитаешь чище; объясни выбор в коммит-сообщении не нужно, просто сделай аккуратно).
4. `.gitignore`: `.venv/`, `_data/`, `__pycache__/`, `*.py[cod]`, `.env`, `*.log`, `.pytest_cache/`,
   `.mypy_cache/`, `.ruff_cache/`. Обязательно поясняющий комментарий по-русски, почему `_data/`
   и `.env` игнорируются (данные питомца и секрет).
5. `tests/test_smoke.py` — pytest-тесты (не требуют Qt):
   - импорт пакета и проверка, что `__version__` соответствует `^\d+\.\d+\.\d+$`;
   - запуск `python -m fly_pet` через `subprocess` с `sys.executable`, `cwd` — корень репозитория,
     проверка кода возврата 0 и подстроки `fly-pet ok` в выводе;
   - `python -m fly_pet --version` возвращает ровно версию пакета;
   - `--help` содержит непустую русскую справку (проверить хотя бы наличие слова `использование` или
     описания; решение оформя сам, но тест должен быть устойчивым к локали).
6. `README.md` (по-русски, коротко и по делу): что это (питомец-муха на рабочем столе), текущее
   состояние («шаг 1: скелет, GUI ещё нет»), как запустить тесты, где будут данные (`_data/`), какие
   гарантии безопасности заложены (только перенос в корзину, никакого удаления, dry-run по умолчанию,
   без автозапуска), и что окружение — проектная venv `.venv`.

## Чего делать нельзя
- Не добавлять зависимости, кроме перечисленных.
- Не импортировать PyQt6/PIL в этом шаге.
- Не создавать конфиги, окна, спрайты, LLM-клиент, действия — это следующие шаги.
- Не менять `docs/plan-stage1.md` и `docs/decisions.md`.
- Не прописывать ничего в автозапуск, ничего не ставить глобально.
- Не создавать файлы вне `D:\Projects\fly-pet`.

## Как проверить свою работу (обязательно выполни сам)
```
.venv/Scripts/python.exe -m fly_pet
.venv/Scripts/python.exe -m fly_pet --version
.venv/Scripts/python.exe -m pytest -q
```
Все три команды должны завершиться успешно; в конце ответа перечисли, что реально вывела каждая
команда, и перечисли созданные/изменённые файлы.
