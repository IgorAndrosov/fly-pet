## Модель поведения (что должно получиться)

**Два режима.**
- **Режим рабочего стола**: муха ходит по плоскости экрана — **в двух измерениях** (и по X, и по Y),
  в любом направлении, а не только по нижней линии. Спрайт разворачивается по направлению движения.
- **Режим окна**: муха ходит **только по одной линии** — вдоль полосы заголовка того окна, на котором
  сидит. По вертикали смещения нет; спрайт развёрнут вправо или влево.
- Смена режима происходит **только во время перелёта** — при посадке: села на стол → режим стола,
  села на полосу окна → режим окна.

**Три вида перелётов** (решаются в момент взлёта, с вероятностями из конфига):
1. **стол → стол**: цель — случайная точка рабочего стола (в двух измерениях, внутри рабочей области
   с отступами), режим остаётся «стол»;
2. **окно → окно**: цель — другое случайное окно из списка кандидатов (не то же самое, если есть
   выбор), режим остаётся «окно»;
3. **стол ↔ окно в обе стороны**: с рабочего стола улетает на окно, с окна — на рабочий стол; при
   посадке режим переключается.

Во время перелёта спрайт тоже развёрнут по направлению полёта.

## 1. `fly_pet/locomotion.py`

- Режим: `LocomotionMode.DESKTOP` / `LocomotionMode.WINDOW`, публичное свойство `mode`;
  сохранять текущий режим в состоянии (`state.mode` уже есть — использовать значения `desktop`/`window`,
  не ломая остальные: `idle`, `sleep` и т.д. пусть пишутся как раньше в тех местах, где уже пишутся).
- Ходьба по столу: направление хранится как угол (градусы). Рывок — движение в этом направлении;
  на паузе с вероятностью `walk.turn_on_pause_chance` направление меняется на случайный угол из
  `walk.desktop_turn_deg` (в любую сторону), иначе остаётся. Отражение от границ рабочей области
  (учитывать `desktop_margin_px`): при упоре в край — зеркальное отражение угла, рывок продолжается.
- Ходьба на окне: как сейчас, строго по горизонтали вдоль полосы; направление только 0° или 180°.
- Цели перелётов:
  - из режима стола: с вероятностью `walk.fly_to_window_chance` летим на случайное окно, иначе —
    в случайную точку стола (`walk.desktop_fly_margin_px` от краёв);
  - из режима окна: с вероятностью `walk.leave_to_desktop_chance` летим на стол, иначе — на другое
    случайное окно (то же окно не выбирать, если кандидатов больше одного).
- Угол поворота спрайта отдавать наружу: метод/свойство, например `sprite_angle_deg()` — угол
  направления движения (0 = вправо, как нарисован спрайт), он же используется при полёте
  (угол от текущей позиции к цели).
- Публичный интерфейс для окна не менять по смыслу: позиция + состояние анимации + угол.

## 2. `fly_pet/window.py`

- Рисовать текущий кадр с поворотом на `sprite_angle_deg()` вокруг центра спрайта
  (`QPixmap.transformed(QTransform().rotate(angle), Qt.TransformationMode.SmoothTransformation)`),
  кэшировать повёрнутые кадры по (имя кадра, угол, округлённый до 5°), чтобы не крутить 20 кадров
  60 раз в секунду.
- При угле 0 отрисовка обязана остаться пиксель-в-пиксель как сейчас (никакого «мыла»).
- Выравнивание по вертикали: на окне муха стоит лапками на полосе заголовка (как сейчас), при
  повороте на 90/270 в режиме стола центр спрайта остаётся в той же точке (не «уезжает» из-за
  смены габаритов повёрнутого изображения).

## 3. Конфиг `config/default.yaml` (блок `walk`, с русскими комментариями)

Добавить: `fly_to_window_chance: 0.5` (с рабочего стола лететь на окно), `leave_to_desktop_chance: 0.5`
(с окна лететь на стол), `desktop_turn_deg: [20, 90]`, `desktop_fly_margin_px: 80`.
Остальные ключи не трогать.

## 4. Тесты (pytest, headless, детерминированно с `walk.seed`)

- режим стола: за 300 шагов меняются **и** X, **и** Y (раньше Y был постоянным);
- режим окна: при ходьбе по окну Y не меняется (высота полосы), меняется только X;
- разворот на паузе в режиме стола меняет угол в пределах `desktop_turn_deg`;
- отражение от краёв: муха не выходит за рабочую область (проверить упор во все четыре края);
- перелёты: с фиксированным сидом доли «на окно» ≈ `fly_to_window_chance`, «на стол» ≈
  `leave_to_desktop_chance` (на 200 решениях, допуск ±10 п.п.); «окно → окно» не выбирает то же окно;
- смена режима происходит только на посадке (во время полёта режим не меняется);
- угол спрайта: для движения вправо ≈ 0, влево ≈ 180, вверх ≈ −90, вниз ≈ 90 (с допуском);
- поворот кадров: при угле 0 результат совпадает с исходным кадром пиксель-в-пиксель.
