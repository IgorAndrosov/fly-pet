# Правка: муха должна садиться на НАСТОЯЩЕЕ окно и быть видимой на нём

## Что измерено владельцем на живом прогоне (это и есть дефект)
Пока муха «шла по окну» (x менялся 926 → 716, y постоянный −42), замер показал:

| Что смотрели | Значение |
|---|---|
| окно в точке центра спрайта мухи | `Chrome_RenderWidgetHostHWND | Chrome Legacy Window` — то есть **рендер чужого окна, а не муха** |
| окно НИЖЕ мухи в z-порядке | `ASUS AsHotkeyExec App Class | ASUS AsHotkeyExec App` |
| окно ВЫШЕ мухи в z-порядке | `Chrome_WidgetWin_1 | Hermes` — **окно, на котором она «идёт», стоит выше неё** |

Вывод: муха привязалась к служебному окну ASUS (невидимый помощник), а настоящее окно приложения
оказалось поверх неё — то есть муху не видно, она ходит за окном. Скриншот это подтвердил: на снимке
окно и ни мухи.

Вторая беда: в кандидаты попадают окна-помощники и невидимые окна с заголовком
(`ASUS AsHotkeyExec App`, `Default IME`, `MSCTFIME UI`, `_q_titlebar` и подобные).

## Что сделать

### 1. Жёсткий отбор окон-кандидатов (`locomotion.py`)
Окно годится, только если ВСЁ перечисленное верно:
- `IsWindowVisible`, не свёрнуто (`IsIconic` = 0), прямоугольник непустой и ≥
  `walk.min_window_width` × `walk.min_window_height`, и хотя бы часть прямоугольника на экране;
- это **окно верхнего уровня без владельца** (`GetWindow(hwnd, GW_OWNER) == 0`) — так отсекаются
  вспомогательные окна приложений;
- НЕТ `WS_EX_TOOLWINDOW`;
- есть стандартная рамка (`WS_CAPTION`) ИЛИ окно можно сделать активным
  (`GetWindowLong` содержит `WS_SYSMENU`) — то есть окно похоже на обычное приложение;
- класс окна не входит в чёрный список служебных: `IME`, `MSCTFIME UI`, `Chrome_RenderWidgetHostHWND`,
  `_q_titlebar`, `Shell_TrayWnd`, `Shell_SecondaryTrayWnd`, `Progman`, `WorkerW`, `SHELLDLL_DefView`,
  `SysListView32`, `DummyDwmListenerWindow`, `AsHotkeyExec`, `ApplicationFrameWindow` (последний — только
  как контейнер, внутрь не садиться);
- заголовок не пустой и не входит в `walk.ignore_titles`.

### 2. Самопроверка после посадки (обязательно)
После `attach_above(target)` и установки позиции, через один-два такта локомоции:
- взять точку центра своего спрайта и вызвать `WindowFromPoint`;
- если там **не наше окно** (например, рендер чужого окна или дочернее окно цели) — считать посадку
  неудачной: `detach_to_desktop()`, вернуться на рабочий стол и выбрать другое окно (не более
  `walk.max_attach_attempts` = 3 попыток подряд, дальше — просто ходьба по столу);
- записать причину в лог (`debug`).

Дочерние окна цели (например, `Chrome_RenderWidgetHostHWND`) считаются «не нашим окном поверх» —
значит, посадка неудачна.

### 3. Дополнительно
- При привязке проверять, что цель ещё жива: `IsWindow(target)` перед каждым `SetWindowPos`.
- Если цель стала невидимой/свернулась/переместилась за экран — улетать сразу (как уже сделано).
- В тестах: отбор кандидатов на подставных описаниях окон (по одному кейсу на каждый пункт фильтра);
  «неудачная посадка → откат на стол» с подменённым `WindowFromPoint`; ограничение попыток.

## Чего делать нельзя
- Делать окно поверх всех окон; ставить хуки; трогать реестр; сеть; меню; еду.
- Менять спрайты (они обновлены на вид сверху), `tools/make_sprites.py`, `docs/plan-stage1.md`,
  `docs/decisions.md`.
- Коммитить.
