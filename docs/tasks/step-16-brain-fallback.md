# Задача 16: мозг питомца — локальная модель primary, DeepSeek резерв

## Что есть сейчас
В коде **нет ни одного обращения к LLM**: есть только секция `llm` в конфиге, ключ `tick.brain_interval_sec`
(120 с) и счётчики `stats.llm_calls` / `stats.llm_failures` в состоянии. Надо сделать мозг и сразу —
цепочку провайдеров с резервом.

## Цепочка провайдеров
Локальная модель на втором ПК (ИИшница, LM Studio, OpenAI-совместимый API) — основная; DeepSeek —
резерв, если локальная не ответила. Порядок задаётся в конфиге, чтобы владелец мог менять без правок кода.

```yaml
llm:
  enabled: true            # выключатель всего мозга
  providers:               # пробуем по порядку, первый ответивший и побеждает
    - name: local
      base_url: http://192.168.0.100:1234/v1
      model: fly-brain
      timeout_sec: 3       # локально ждём мало: не ответил — сразу резерв
      api_key_env: null    # локальному серверу ключ не нужен
    - name: deepseek
      base_url: https://api.deepseek.com
      model: deepseek-chat
      timeout_sec: 30
      api_key_env: DEEPSEEK_API_KEY   # значение только из окружения, в конфиге его нет
  max_tokens: 256
  temperature: 0.4
  phrase_ttl_sec: 5
```
Старые ключи `base_url` / `model` в `llm` оставить работающими как синоним одного провайдера (обратная
совместимость с уже записанным конфигом).

## Поведение
1. `fly_pet/brain.py`: клиент OpenAI-совместимого `/v1/chat/completions` (httpx уже в зависимостях).
   Проходит провайдеров по порядку; **переходит к следующему** при: ошибке соединения, таймауте,
   HTTP ≥ 400, пустом/неразборном ответе. Первый успешный — победитель.
2. Запрос: короткая русская реплика (одна фраза, ≤ 12 слов) **и, если получится, действие** из белого
   списка `actions` (значения брать из конфига, валидировать в коде; неизвестное действие — отбросить).
   Реплика уходит в облачко (`window.say`), действие пока только логируется (реальные действия — по
   `safety`, не в этой задаче).
3. **Никогда не блокировать интерфейс.** Запрос — в отдельном потоке (`QThread`/`threading`), результат
   приходит в GUI-поток через сигнал Qt. Пока ответа нет — питомец живёт как обычно, без «замираний».
4. Учёт: `stats.llm_calls` +1 на успешный ответ, `stats.llm_failures` +1, если ответили не все провайдеры.
   В состояние также писать `stats.llm_last_provider` (кто ответил) — по нему видно, работает ли локальная.
5. Логи INFO: `ответил провайдер <name> (<ms> мс)`; при переходе к резерву — WARNING один раз на серию
   отказов, а не каждый тик (чтобы лог не забивался, когда ИИшница выключена). Ключ в лог не попадать
   (в `logging_setup` уже есть вырезание секретов — не отключать).
6. Если не ответил никто: реплика из шаблонов (`phrases.py`), запись в лог WARNING, питомец работает
   дальше. Никаких исключений наружу, никаких падений.
7. Ключ читать только из окружения. При запуске — подгружать `C:\Users\igora\AppData\Local\hermes\.env`
   тем же способом, что уже используется в проекте (если способа нет — добавить аккуратный загрузчик
   `.env` без зависимостей, не перезаписывая уже заданные переменные).
