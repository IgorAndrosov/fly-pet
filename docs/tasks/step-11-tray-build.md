# Задача 8: курсор отпугивает муху, иконка в трее, сборка в exe

Работай только внутри `D:\Projects\fly-pet`. Ничего не устанавливай (PyInstaller ставит владелец).
Другие проекты и `D:\hermes` не трогай. Тексты и комментарии — по-русски, UTF-8 без BOM.

Контекст: `docs/decisions.md`, `docs/plan-stage1.md`. Сейчас работает: прозрачное окно со спрайтом
(вид сверху, поворот по направлению движения), локомоция с двумя режимами (стол — в двух измерениях,
окно — по полосе заголовка), перелёты стол↔окно, рывки/паузы/потирание лапок, потребности, облачко
реплик, сторож рабочего стола, фильтр окон и привязка в z-порядке. Запуск: `python -m fly_pet --gui`.

Файлы: `fly_pet/{app,window,locomotion,config,state,needs,bubble,phrases,animation,logging_setup}.py`,
спрайты `assets/fly/*.png` (22 кадра), иконки `assets/fly_pet.png` и `assets/fly_pet.ico` (готовы,
не перерисовывать), `config/default.yaml`, `_data/settings.yaml` — правки пользователя (побеждают).

## 1. Курсор отпугивает муху (вместо меню по мухе — меню на ней НЕ делать)

- В такте локомоции (`walk.tick_ms`) читать позицию курсора (`GetCursorPos` через ctypes, платформенно;
  на не-Windows — no-op).
- Если `walk.scare_cursor: true` (по умолчанию true), муха не тащится мышью прямо сейчас (кнопка не
  зажата на ней) и прошёл `walk.scare_cooldown_sec` с прошлого испуга:
  - расстояние от курсора до центра мухи < `walk.scare_radius_px` → **немедленный рывок в сторону от
    курсора** (направление — вектор «от курсора к мухе», длина рывка `walk.scare_burst_px`,
    скорость `walk.scare_speed_px_s`), состояние `walk` на `dash_animation_fps`;
  - это же расстояние < `walk.panic_radius_px` → **паника**: взлёт и перелёт в другое место
    (по тем же правилам, что обычный перелёт: случайная точка стола или другое окно);
  - после срабатывания — кулдаун, чтобы не дёргалась непрерывно.
- Пока пользователь держит левую кнопку на мухе (перетаскивание) — она не пугается и не убегает.
- На окне (режим окна) убегает вдоль полосы; при панике — улетает.
- Запись в лог `debug` при испуге: расстояние, направление, был ли рывок или паника.
- В конфиг: `scare_cursor: true`, `scare_radius_px: 90`, `panic_radius_px: 40`,
  `scare_burst_px: [110, 240]`, `scare_speed_px_s: 340`, `scare_cooldown_sec: 1.2`.
- **Никакого контекстного меню на самой мухе** — управление только через трей (ниже).

## 2. Иконка в трее `fly_pet/tray.py`

- `QSystemTrayIcon` с иконкой из `assets/fly_pet.png` (берётся через `resource_dir()`, см. п. 3),
  подсказка «Муха-питомец».
- Меню по-русски:
  - «Спрятать муху» / «Показать муху» (пункт меняет подпись; двойной клик по иконке — то же);
  - «Стоять на месте» (флаг: муха не ходит и не летает, только сидит; повторный выбор снимает);
  - «Спать» / «Проснуться»;
  - «Не бояться курсора» (галочка, меняет `scare_cursor` на лету);
  - «Отчёт о работе» (заглушка: показывает облачко с фразой-отчётом — реальный отчёт придёт позже);
  - «О программе» (`QMessageBox` с версией и коротким описанием);
  - «Выход» — **корректное завершение**: сохранить состояние, остановить таймеры, `quit()`.
- Если `QSystemTrayIcon.isSystemTrayAvailable()` ложно — предупреждение в лог и работа без трея.
- Трей не должен красть фокус и мешать мухе.

## 3. Пути для сборки: `fly_pet/paths.py`

Новый модуль с тремя функциями:
- `resource_dir()` — папка ресурсов внутри сборки: при `getattr(sys, "frozen", False)` это
  `Path(sys._MEIPASS)`, иначе корень репозитория;
- `app_dir()` — папка приложения: при сборке — папка exe (`Path(sys.executable).parent`), иначе корень;
- `default_data_dir()` — каталог данных: `app_dir() / "_data"`, чтобы сборка была переносимой.
Применить: `config.load_config` (дефолтный конфиг из `resource_dir()/config/default.yaml`),
`app.py` (спрайты из `resource_dir()/assets/fly`), каталог данных по умолчанию — `default_data_dir()`
(приоритеты сохранить: аргумент → `FLY_PET_DATA_DIR` → дефолт). Обычный запуск из репозитория не
должен измениться ни в чём.

## 4. Сборка в exe: `tools/build_exe.py`

Скрипт запускается проектным питоном и делает **две** сборки PyInstaller в `dist/`:
- `dist/fly-pet/` — вариант «папка» (`--onedir`);
- `dist/fly-pet-onefile.exe` — вариант «один файл» (`--onefile`).
Общие параметры: `--noconsole` (окна консоли нет), `--icon assets/fly_pet.ico`,
`--add-data "assets;assets"`, `--add-data "config;config"`, `--name` как в путях выше,
`--noconfirm`, `--clean`, `--exclude-module PyQt6.QtWebEngineCore` и прочие тяжёлые модули Qt,
которые не используются (перечисли, какие исключил, и почему). Скрипт печатает итоговые пути и
размеры. Ошибка сборки должна быть видна (ненулевой код возврата).
Добавь в `.gitignore`: `build/`, `dist/`, `*.spec`.

Дополнить по-русски: как собрать (`python tools/build_exe.py`), где лежат готовые сборки, чем

## Чего делать нельзя
- Рисовать/менять спрайты и иконки, трогать `tools/make_sprites.py`, `docs/`.
- Делать автозапуск, писать в реестр, ставить хуки клавиатуры/мыши (курсор читаем опросом, не хуком).
- Менять модель локомоции и вероятности перелётов, ломать потребности/облачко.
- Коммитить, ставить пакеты, собирать exe самостоятельно (владелец соберёт сам).

## Как проверить свою работу (обязательно выполни сам)
```
.venv/Scripts/python.exe -m pytest -q
QT_QPA_PLATFORM=offscreen .venv/Scripts/python.exe -m fly_pet --gui   (2-3 секунды, что не падает)
.venv/Scripts/python.exe tools/build_exe.py --dry-run                 (если сделаешь такой режим: печатает команды без запуска)
```
В отчёте: вывод pytest, что именно добавил в конфиг и в пути, какие модули исключил из сборки,
и какие команды PyInstaller сформирует скрипт.
