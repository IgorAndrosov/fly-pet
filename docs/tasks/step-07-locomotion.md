# Задача 5: муха ходит по рабочему столу, взлетает и садится на чужие окна

Работай только внутри `D:\Projects\fly-pet`. Ничего не устанавливай (venv готова: PyQt6, Pillow, PyYAML,
httpx, pytest). Другие проекты и `D:\hermes` не трогай. Все тексты и докстринги — по-русски, UTF-8 без BOM.
Контекст и обязательные решения: `docs/decisions.md`, `docs/plan-stage1.md`.

Уже есть: окно со спрайтами (`window.py`: прозрачное, frameless, не поверх всех, перетаскивание,
`set_click_through`, `never_minimize`, `tool_window`, сторож `desktop_reassert`), анимации
(`animation.py`), потребности и облачко (`needs.py`, `bubble.py`, `phrases.py`), конфиг/состояние/логи,
запуск `python -m fly_pet --gui`.

Спрайты: добавлены новые кадры — `assets/fly/fly_1.png`…`fly_4.png` (полёт) и `assets/fly/land_1.png`
(приземление); состояния для аниматора: `fly` и `land` рядом с существующими
`idle/walk/sleep/chew`. Регенератор — `tools/make_sprites.py` (не менять).

## Что должно получиться (поведение)
1. **Муха ходит по рабочему столу.** Внизу рабочей области (над панелью задач), настраиваемым отступом
   от края, шагом вперёд с переворотом спрайта по направлению; изредка останавливается (idle).
2. **В случайный момент взлетает** — состояние `fly`, подъём по дуге вверх.
3. **Садится на случайное открытое окно, на его верхнюю полосу** (та, за которую окно перетаскивают),
   и дальше **ходит по этой полосе внутри окна**: муха должна казаться находящейся на самом окне, а не
   висящей над ним отдельным окном. Для этого её окно вставляется в z-порядок непосредственно над
   целевым окном и следует за ним.
4. **Через случайное время улетает** — либо на другое случайное окно, либо обратно на рабочий стол.

## 1. Новый модуль `fly_pet/locomotion.py`

**Список окон** (`EnumWindows` через ctypes, как уже сделано в `window.py`):
- берём только видимые, не минимизированные, не `WS_EX_TOOLWINDOW`, не принадлежащие нашему процессу,
  с непустым заголовком, шириной ≥ `walk.min_window_width` и высотой ≥ `walk.min_window_height`;
- исключаем классы рабочего стола и оболочки: `Progman`, `WorkerW`, `SHELLDLL_DefView`, `SysListView32`,
  `Shell_TrayWnd`, `Shell_SecondaryTrayWnd`, а также заголовки из `walk.ignore_titles`;
- результат — список объектов `WindowInfo(hwnd, title, class_name, rect, is_foreground)`; при пустом
  списке поведение «только рабочий стол» без падения.

**Полоса заголовка** (`title_bar_strip(info) -> Rect`):
- если у окна есть стандартная рамка (`WS_CAPTION`), полоса = от верха окна до
  `SM_CYCAPTION + SM_CYFRAME` (через `GetSystemMetrics`);
- иначе (современные окна с собственной отрисовкой заголовка) — от верха окна до верха клиентской
  области (`GetClientRect` + `ClientToScreen`), но не выше 44 px и не ниже 24 px;
- если полоса получается вырожденной — окно в кандидаты не берём.

**Z-порядок**:
- `attach_above(hwnd_target)` — `SetWindowPos(наше_окно, hwnd_target, 0, 0, 0, 0, SWP_NOMOVE | SWP_NOSIZE |
  SWP_NOACTIVATE)`: встаём непосредственно над целевым окном (значит, при уходе окна в фон муха уходит
  вместе с ним, а не висит поверх всего);
- `detach_to_desktop()` — ставимся над окном рабочего стола (найденный `SysListView32`/`Progman`;
  если не найдено — прежнее поведение со сторожем `desktop_reassert`).

**Состояния** (`LocomotionState`, шаг `step(dt_sec)`):
`ON_DESKTOP` (ходьба по столу) → `TAKEOFF` (короткий подъём, `fly`) → `IN_FLIGHT` (полёт к целевой точке,
смена кадров `fly`) → `LANDING` (`land`, короткая пауза) → `ON_WINDOW` (ходьба по полосе заголовка) →
`TAKEOFF`/`IN_FLIGHT` обратно на стол или к другому окну.
- Скорости и тайминги — из конфига (ниже). Случайные интервалы брать из `random.Random`, сид можно
  задать в конфиге (`walk.seed`, по умолчанию null) — это нужно для тестов.
- Пока муха на окне: на каждом шаге пересчитывать позицию из **текущего** прямоугольника целевого окна
  (окно двигают/меняют размер — муха едет вместе с ним), ходьба по полосе с отражением от краёв.
- Если целевое окно исчезло, скрылось, свернулось или стало нулевым — сразу `TAKEOFF` в сторону
  рабочего стола, без исключений и падений.
- Направление движения влияет на отражение спрайта по горизонтали (зеркало, без новых файлов).

## 2. Интеграция

- `window.py`: метод `set_locomotion(loc)` или прямая связка — по таймеру `walk.tick_ms` окно
  спрашивает у локомоции позицию и состояние анимации (`walk`/`idle`/`fly`/`land`) и переставляет себя
  (`move`) + переключает кадры; `animation.py` учит состояния `fly` и `land` (просто находит файлы
  `fly_*.png`, `land_*.png` в `assets/fly`).
- Перетаскивание мышью человеком имеет приоритет: пока пользователь тащит муху, локомоция
  приостанавливается; после отпускания — снова с рабочего стола.
- Сторож `desktop_reassert` продолжает работать, но **не должен** поднимать муху, когда она законно
  находится на чужом окне (проверять состояние локомоции).
- Потребности/облачко не ломаем: реплики по-прежнему показываются, облачко следует за мухой
  (в том числе когда она на чужом окне).

## 3. Конфиг `config/default.yaml` (новый блок, с русскими комментариями)

```yaml
walk:
  enabled: true
  tick_ms: 40                     # период шага локомоции
  desktop_speed_px_s: 26          # скорость ходьбы по столу
  window_speed_px_s: 22           # скорость ходьбы по полосе окна
  fly_speed_px_s: 520             # скорость полёта
  desktop_margin_px: 12           # отступ от низа рабочей области
  desktop_stay_sec: [8, 25]       # сколько ходит по столу до взлёта
  window_stay_sec: [6, 18]        # сколько живёт на одном окне
  pause_chance: 0.15              # шанс остановиться на шаге (idle)
  min_window_width: 320
  min_window_height: 160
  ignore_titles: []               # заголовки, на которые садиться нельзя
  seed: null                      # сид генератора (для тестов)
```

## 4. Тесты (pytest, headless, `QT_QPA_PLATFORM=offscreen`)

Вся работа с Win32 — за тонким слоем, который в тестах подменяется (никакого реального
`EnumWindows` в тестах):
- выбор цели: пустой список → остаёмся на столе; исключения по заголовку/размеру/классу работают;
- полоса заголовка: для окна со стандартной рамкой и для окна с собственной отрисовкой
  (проверить обе ветки и минимумы 24/44 px);
- ходьба по столу: за N шагов муха смещается на ожидаемое расстояние, отражается от краёв;
- полёт: за время полёта позиция монотонно приближается к цели, по прибытии меняется состояние;
- на окне: при сдвиге целевого окна на (dx, dy) позиция мухи сдвигается на те же (dx, dy);
- исчезновение цели в состоянии `ON_WINDOW` → переход в `TAKEOFF`, без исключений;
- детерминизм при заданном `walk.seed` (два прогона дают одинаковую последовательность состояний);
- `animation`: кадры `fly`/`land` находятся, количество совпадает с файлами.

- Сеть, LLM, меню, еда — следующие шаги.
- Менять спрайты, `tools/make_sprites.py`, `docs/plan-stage1.md`, `docs/decisions.md`.
- Коммитить.
