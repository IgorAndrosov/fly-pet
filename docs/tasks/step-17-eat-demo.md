## Что сделать

### 1. Действие «съесть файл» — один код-путь, два триггера
- `fly_pet/actions.py` (или `eat.py`): функция `demo_eat(desktop_path: Path) -> None`, которая по шагам:
  1) создаёт тестовый файл на рабочем столе (см. п.2) — если создание не удалось, реплика об ошибке и выход;
  2) просит explorer обновиться (`SHChangeNotify(SHCNE_CREATE, SHCNF_PATHW, path, None)`) и **ждёт до 5 с**,
     пока иконка файла появится в `SysListView32`; берёт её **экранные координаты** (с учётом DPI);
     если не нашлась — WARNING в лог, реплика «не вижу файл» и выход без перемещений;
  3) даёт локомоции команду «лететь в точку» (центр иконки, чуть выше — муха садится НА иконку);
  4) по прилёту — состояние `chew` на 1.5–2.5 с (можно 2–3 цикла жевания), реплика в облачко;
  5) в конце жевания **переносит файл** в карантин `_data/trash/` (имя сохранить; при совпадении —
     добавить метку времени). **Никакого удаления.**
  6) после — питомец возвращается к обычной жизни (ходьба/перелёты продолжаются).
- Триггеры — оба вызывают одну и ту же функцию:
  - пункт меню трея **«Тест: создать файл и съесть»** (по-русски, рядом с остальными пунктами);
  - CLI-флаг `--demo-eat` (нужен владельцу и мне для проверки без кликов по трею).
- Действие это **пользовательское** (нажал владелец), поэтому оно не подчиняется `dry_run`: файл реально
  переносится в карантин. Но в лог писать явно: `demo eat (по кнопке)`, и никаких удалений, никаких
  файлов вне созданного нами тестового.

### 2. Тестовый файл
- Имя — узнаваемое и с префиксом, например `муха-демо.txt`; содержимое — пара строк текста.
- Место — **рабочий стол владельца** (путь из реестра `User Shell Folders\Desktop`, у владельца это папка
  OneDrive) — иначе иконки на рабочем столе не будет и подлетать будет некуда.
- Если демо запускается повторно — старый тестовый файл сначала убрать в карантин, новый создать.

### 3. Полёт в точку (локомоция)
- Добавить в `Locomotion` метод вида `fly_to(x: int, y: int, on_arrive: callable | None = None)`:
  взлёт → полёт по прямой к точке → посадка → обратный вызов. По завершении — обычное поведение.
- Ничего в существующих режимах не ломать: случайные перелёты, посадки на чужие окна, испуг курсором,
  временный topmost при показанном рабочем столе, `desktop_reassert`.

### 4. Учёт и логи
- В `state.stats` добавить `eaten` (счётчик съеденных тестовых файлов) — поле уже есть в схеме состояния.
- Логи INFO по шагам: создал файл, нашёл иконку (координаты), полетел, прилетел, прожевал, перенёс в карантин.
- Реплики в облачке — короткие, по-русски (например: «Нашла!», «Ммм…», «Съела!»). Тексты — в `phrases.py`.

## Как проверять (мой обязательный прогон)
```bash
cd D:/Projects/fly-pet
FLY_PET_DATA_DIR=D:/Projects/fly-pet/_data_check .venv/Scripts/python.exe -m fly_pet --demo-eat --gui
```
Критерии приёмки:
1. на рабочем столе появился тестовый файл (проверяю файловой системой);
2. в логе есть строка с **координатами иконки**, и они попадают в прямоугольник рабочего стола;
3. муха **реально перемещается** к этим координатам (замер: её прямоугольник сходится к координатам иконки);
4. файл исчезает из рабочего стола и появляется в `_data_check/trash/` (проверяю файловой системой —
   файл не удалён, а перенесён);
5. `stats.eaten` увеличился на 1; в облачке была реплика;
6. **муха продолжает рисоваться** после всего этого (снимок экрана: внутри её рамки меняются пиксели —
   отрисовка не должна ломаться, это уже дважды кусалось);
7. `pytest -q` зелёный; остальное поведение (испуг курсором, Show Desktop) не сломано.

## Чего нельзя
- Удалять файлы (только перенос в карантин), трогать файлы вне созданного нами тестового.
- Расширять белый список расширений или разрешать реальные действия для модели (это по-прежнему за `safety`).
- Делать меню на самой мухе.
- Трогать спрайты, LLM/мозг, сборку. Коммитить, ставить пакеты, собирать exe — тоже не надо.
