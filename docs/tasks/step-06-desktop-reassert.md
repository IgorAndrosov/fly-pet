# Правка: после «Показать рабочий стол» (Win+D / кнопка в углу панели задач) муха должна оставаться видна

## Что измерено (владельцем, на живом окне)
При сворачивании всех окон окно питомца **не сворачивается и не скрывается** — но его накрывает
рабочий стол. Замеры `WindowFromPoint` в центре мухи и `GetForegroundWindow`:

| Момент | В фокусе | В точке мухи | Наше окно |
|---|---|---|---|
| обычное состояние | `Chrome_WidgetWin_1` «Hermes» | `Qt6112QWindowToolSaveBits` «fly-pet» (наше) | видимо, не свёрнуто |
| после Show Desktop | `Progman` «Program Manager» (pid explorer) | `SysListView32` «FolderView» (pid explorer) | видимо, не свёрнуто — просто перекрыто |
| после возврата окон | `Chrome_WidgetWin_1` «Hermes» | обычное окно | видимо |

Итог: нужен «сторож», который замечает, что поверх окна питомца лежит именно рабочий стол, и
возвращает питомца наверх — **только в этом случае**, чтобы обычные окна по-прежнему перекрывали муху
(это осознанное решение владельца: окно не «поверх всех окон»).

## Что сделать

1. Конфиг `config/default.yaml`, секция `window` — два новых ключа с русскими комментариями:
   - `desktop_reassert: true` — включать «сторожа»;
   - `desktop_reassert_ms: 800` — период проверки, миллисекунды.

2. `fly_pet/window.py`:
   - новый QTimer с периодом `desktop_reassert_ms` (только если `desktop_reassert`);
   - на каждом тике:
     а) если окно свёрнуто — вернуть в нормальное состояние; если скрыто — `show()`;
     б) определить окно в центре питомца через `WindowFromPoint` (Win32, ctypes; координаты — центр
        окна, при выходе за экран — ближайшая внутренняя точка);
     в) если это окно **не наше** и его класс — один из окон рабочего стола
        (`Progman`, `WorkerW`, `SHELLDLL_DefView`, `SysListView32`), либо `GetForegroundWindow()`
        имеет класс `Progman`/`WorkerW` — поднять наше окно наверх **без активации**:
        `SetWindowPos(hwnd, HWND_TOP, 0, 0, 0, 0, SWP_NOMOVE | SWP_NOSIZE | SWP_NOACTIVATE)`;
     г) во всех остальных случаях ничего не делать (обычное окно поверх мухи — норма, не боремся);
   - классы для сравнения и вспомогательные вызовы Win32 держать в одном небольшом приватном
     хелпере (например `_is_desktop_on_top()`), чтобы его можно было подменить в тестах без GUI;
   - на не-Windows — no-op с предупреждением в лог (как в `set_click_through`);
   - писать `debug`-строку в лог при возврате наверх (не чаще одного раза на подъём).

3. Тесты (`QT_QPA_PLATFORM=offscreen`), `tests/test_window_headless.py` (или новый файл):
   - при `desktop_reassert: true` таймер создан с интервалом из конфига; при `false` — не создан
     или не запущен;
   - подмени хелпер `_is_desktop_on_top()` на «True» и убедись, что вызывается подъём наверх
     (например, считать вызовы через monkeypatch `SetWindowPos`-обёртки) — тест не должен зависеть
     от реального рабочего стола;
   - при «False» подъём НЕ вызывается;
   - свёрнутое окно возвращается в нормальное состояние на тике сторожа.

4. `README.md` — дополнить раздел «Поведение на рабочем столе»: после «свернуть все окна» / `Win+D`
   муха возвращается на рабочий стол (сторож срабатывает только на рабочий стол, обычные окна её
   по-прежнему перекрывают).

## Чего делать нельзя
- Не делать окно always-on-top и не поднимать его над обычными окнами.
- Не трогать еду, меню, LLM, потребности, спрайты, `docs/plan-stage1.md`, `docs/decisions.md`.
- Не коммитить, ничего не устанавливать.


выполни в PowerShell `$s = New-Object -ComObject Shell.Application; $s.ToggleDesktop()`, подожди
2 секунды и проверь `WindowFromPoint` в центре окна питомца (скрипт-заготовка:
`C:\Users\igora\AppData\Local\hermes\cache\scratch\probe_desktop_signals.py`). Ожидаемый итог:
после сворачивания окон в точке мухи снова **наше окно** («fly-pet»), а не `SysListView32`.
Обязательно верни окна обратно вторым `ToggleDesktop()`, выключи питомца и прибери за собой
(`_data/settings.yaml`, `_data/state.json`). В отчёте приведи реальный вывод проверок.
