# Зафиксированные решения (по итогам обсуждения плана)

Документ для разработки: здесь то, что согласовано с владельцем проекта. Если код расходится с этим
файлом — прав файл, а не код.

## Окно и поведение на экране
- Обычное frameless-окно **без always-on-top**: муха живёт на уровне рабочего стола, любое окно её
  перекрывает. Клик сквозь (`click_through`) по умолчанию выключен, чтобы работало контекстное меню.
- Действия выполняются независимо от видимости окна: если муху перекрыли, файл всё равно убирается,
  просто анимации не видно.
- Реплики — только всплывающим облачком на экране. Telegram и другие каналы не используются.
- Спрайты — рисуются процедурно (Pillow), до внедрения показываются владельцу на утверждение.

## Что и как ест
- Источник еды — **личный рабочий стол**: путь читается из реестра
  (`HKCU\...\Explorer\User Shell Folders` → `Desktop`), у владельца это
  `C:\Users\igora\OneDrive\Рабочий стол`.
- Общий рабочий стол `C:\Users\Public\Desktop` **не трогается** (ярлыки всех пользователей).
- Едятся только **файлы**, не папки.
- Никогда не трогаются: `.lnk`, `.url`, `desktop.ini`, скрытые и системные файлы, файлы в
  отмеченных «не трогать» папках.
- Возраст: файл не трогается, если `max(время обращения, время изменения)` моложе 7 дней
  (обновление времени обращения на машине включено — проверено `fsutil behavior query disablelastaccess`
  → `DisableLastAccess = 2`, ENABLED).
- «Удаление» = **перенос** в `_data/trash` с сохранением структуры путей. Удалять файлы питомец не
  умеет вообще. Обратный перенос — одной командой.
- Белый список расширений по умолчанию **пуст**: пока владелец ничего не разрешил, питомец только
  докладывает («голодна, есть нечего»).
- Исключения сильнее белого списка: «не трогать» всегда побеждает.
- Наполнение списка — через контекстное меню по правому клику на мухе (плюс правка YAML руками).

## Безопасность
- `dry_run: true` по умолчанию. Реальные переносы — только при `dry_run: false` **и**
  `allow_real_actions: true`.
- Действия модели валидируются по белому списку дважды: в промпте и в коде. Пути и параметры берутся
  из конфига, не от модели.
- Каждое решение и действие пишется в лог. Ключ API в код, логи и репозиторий не попадает.
- Никаких глобальных установок и никакого автозапуска.

## Данные и настройки
- Данные проекта: `D:\Projects\fly-pet\_data\` → `state.json`, `logs/`, `trash/`, `settings.yaml`.
- `_data/` исключена из git (`.gitignore`) и из Syncthing (строка в `D:\Projects\.stignore`), иначе
  корзина и логи уедут на второй ПК.
- Дефолты — `config/default.yaml` в репозитории; правки владельца (в том числе из меню) —
  `_data/settings.yaml`; питомец читает «дефолт + правки».

## Мозг
- LLM DeepSeek по API, ключ из `DEEPSEEK_API_KEY` (окружение; на машине лежит в `hermes\.env`).
- Локальные модели не поднимаются. Electron не используется.
- Строгий JSON-ответ `{action, say, reason}`, `action` — только из белого списка или `null`.
- При сбое сети/парсинга — локальный фолбэк (сон, доклад), а не падение.

## Действия (набор)
1. `eat_desktop_file` — уборка рабочего стола с анимацией поедания; при пустом белом списке —
   только доклад.
2. `report` — отчёт питомца о своей работе.
3. `idle_nudge` — реакция на долгое бездействие пользователя.
4. `sleep` — сон при простое / низкой энергии.

## Технические решения
- Python 3.13, PyQt6 и Pillow — в проектной venv `D:\Projects\fly-pet\.venv` (глобально ничего).
- Пакет — плоский `fly_pet/` в корне репозитория (запуск `python -m fly_pet` без установки пакета).
  Отличие от исходного плана (`src/fly_pet/`) сделано ради запуска без `pip install -e .`.
- Иконка файла — `SHGetFileInfoW` (проверено вживую: иконки `.torrent`, `.png`, папки, документа
  снимаются с прозрачностью); в проекте размер 48×48.
- Координаты иконок на рабочем столе — точный режим (окно `Progman → SHELLDLL_DefView → SysListView32`,
  `LVM_GETITEMPOSITION` через память explorer'а); при любом сбое — тихий откат на фиксированную точку
  из конфига, настоящая иконка исчезает в тот же момент.
- Позиции иконок читаются в режиме, не требующем прав администратора.
- После Show Desktop (`Win+D`) муха остаётся видимой через **временный `SetWindowPos(HWND_TOPMOST)`**
  (с корректными ctypes-прототипами), а не через `SetParent(Progman)` и не через `SetWindowBand`:
  `SetParent` на Qt-окне убивает отрисовку безвозвратно; `SetWindowBand(ZBID_DESKTOP)` даёт
  `ERROR_ACCESS_DENIED` (5) без uiAccess; обычный `HWND_TOP` оставляет окно под `Progman`.
  Сторож `desktop_reassert` детектит накрытие столом; topmost включается/снимается только на
  переходе (гистерезис 2/3 тика). Постоянный `WS_EX_TOPMOST` / `always_on_top` запрещён.

## Этап 2 (отложено)
- Спайковая connectome-модель **мозга дрозофилы** (аналог `abgnydn/webgpu-fly`: реальные веса FlyWire,
  LIF-нейроны) вместо скриптовой локомоции. Подключение планируется в будущих обновлениях; на выходе —
  «скорость ходьбы + смещение поворота», спрайт становится исполнителем. В этапе 1 — только задел:
  интерфейс `LocomotionDriver.set_velocity(vx, turn)` с пустой реализацией. Если модель не заведётся на
  текущем железе — остаются скриптовые анимации, о чём сообщается прямо.
